pxv guide build

Authoritative sources: operator-en.md, operator-pl.md, user-en.md and user-pl.md
under source/markdown. The edition list is configured once in build-manifest.json.
Theme: assets/brand.json with the same brandName as product.json.

From the matching source checkout, with pinned dependencies installed:
  pxv guides rebuild --chromium /usr/bin/google-chrome
For HTML only:
  pxv guides rebuild --html-only
For another destination:
  pxv guides rebuild --output-dir output/pdf --chromium /usr/bin/google-chrome

The command builds the workspace, then calls tools/optional/publishing/rebuild.mjs.
Installed packages contain guide sources and build configuration, not the renderer.
No browser download, dependency installation, device access or publication occurs.

Each edition creates HTML, an A4 office PDF and a color print PDF with 216 x 303 mm
media, an A4 TrimBox and 3 mm bleed. The print output is not PDF/X and has no
commercial printer profile. Office PDFs use less ink and include page numbers.

PDF builds require an explicitly selected Chromium and Poppler tools pdfinfo,
pdftotext, pdffonts and pdftoppm. Hashes, extracted text, page counts, font checks,
page boxes and one PNG per page are recorded in qa/manifest.json. --no-render
skips PNG generation; --html-only does not run Chromium or Poppler.

Review every rendered page before distribution. QA records describe only the
actual document build. Device status belongs to the project handoff report.
Generated guide files and qa/ are local build outputs; keep reviewed copies with
the matching release. Never put credentials or device-specific records in guides.
