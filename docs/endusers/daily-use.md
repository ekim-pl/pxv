# Daily use of your prepared phone

Keep the profile list, actual support route, and general quick start available.
Store private credential inserts elsewhere. Use the handoff notes for the apps,
network requirements, and limitations of your installation.

## Choose, unlock, and leave a profile

If you have only Owner, no user switching is needed. Otherwise open the Android
user switcher and select the profile intended for the activity. Check its name and
apps before entering private information. Unlock with that profile’s ordinary
credential; see [PINs and duress](pins-passwords-and-duress.md) if uncertain.

Ask the operator to demonstrate switching, locking, and ending a secondary session
on the installed build. Follow that demonstrated method when finishing work. Do
not delete and recreate a profile as a troubleshooting shortcut.

## Work within account and app boundaries

Each profile needs its own supported sign-ins and private imports. The same app
icon in two profiles does not establish that they use the same service account.
Confirm which Session account or phone number belongs to an activity before sharing
an identifier. Keep work and personal information in their intended profiles.

Package versions are shared by Android users, while app data and many settings are
separate. Coordinate managed-app removal, updates, permission changes, VPN changes,
and profile layout changes with the operator. A previous acceptance report may no
longer cover the changed configuration.

## When something stops working

| Problem | First steps |
| --- | --- |
| App/account missing | Check the active profile and your packet’s promised configuration; report the discrepancy. |
| Ordinary unlock fails | Check the intended profile and credential type. Do not try duress values; contact the operator through the agreed route. |
| Internet/app connection fails | Check the current profile, available network, approved VPN app and visible error; retain required protections. |
| Import/setup screen differs | Stop that step and request the approved private/manual method for the installed build. |
| Profile disappeared or identity changed | Preserve the current state and request inspection; recreating a name does not restore its old identity. |
| Request to reset/reinstall or enable debugging | Arrange a supervised maintenance visit and discuss backups and renewed acceptance. |

Support needs the asset label, affected profile/app, time, and a value-free problem
description. Exclude account passwords, MFA/recovery material, ordinary unlocks,
duress values, and wipe keys from messages and screenshots.

Continue with [backup, loss, and support](backup-loss-and-support.md) for repairs,
missing phones, account recovery, or maintenance that changes the installation.
